# 电子宠物 — 产品设计规格

**日期：** 2026-09-14  
**形态：** 单词抓抓乐 PWA 内嵌玩法（非独立 Tab）  
**范围：** 一孩一宠、学习换粮、手动喂食、三日未喂死亡、显隐开关

---

## 1. 目标与约束

**目标：** 用一只常驻电子宠物把「每天完成三关」变成可积累的照料循环，增加趣味，但不打断学习主线。

**用户：** 孩子为主；显隐开关孩子可自己点。

**硬约束：**
- 完成早 / 午 / 晚各关各得 1 份粮食，可累积
- 手动喂食；每天喂 1 次即可（花 1 粮）
- 连续 3 个自然日未喂 → 死亡
- 死亡可花 3 粮复活（复活当天算已喂）
- 可显示 / 隐藏；隐藏后后台仍计饥饿与死亡
- 进度按 `ChildProfile` 隔离，随账号云同步

**非目标：** 升级进化、装扮商城、多宠物、社交、自动喂食、语音互动。

---

## 2. 方案

轻量浮窗宠物：在带底部导航的主页面（今日 / 词库 / 错词 / 我的）右下角常驻。学习关卡页不出现，避免抢注意力。

---

## 3. 数据模型

新增 `Pet`（一孩一宠，`childId` 唯一）：

| 字段 | 含义 |
|------|------|
| `species` | `cat` \| `dog`，领养后不可换种 |
| `name` | 默认「小猫 / 小狗」，可选自定义，最多 8 字 |
| `foodBalance` | 粮食库存，≥ 0，可累积 |
| `lastFedDateKey` | 最近喂食日 `YYYY-MM-DD`；从未喂过为 `null` |
| `status` | `alive` \| `dead` |
| `visible` | 是否在页面显示 |
| `adoptedAt` | 领养时间 |

`ChildProfile` 增加 `pet Pet?`。完关发粮只在宠物已领养时入账；未领养前完成的关不补发（领养弹层在首次进入主页面即出现，默认会先领养）。

---

## 4. 规则（纯函数，可单测）

自然日按本地 `dateKey()`（`YYYY-MM-DD`）。

**参照日：** `lastFedDateKey`；若从未喂过，用领养日的 `dateKey(adoptedAt)`。

**未喂天数 `daysUnfed`：** 今天相对参照日的整日差。

**读状态时结算：** 若仍标记 `alive` 且 `daysUnfed >= 3`，写成 `dead`。

**心情 `mood`（给 UI）：**

| 条件 | mood |
|------|------|
| `dead` 或 `daysUnfed >= 3` | `dead` |
| `lastFedDateKey === 今天` | `full` |
| `daysUnfed >= 2` | `critical` |
| 其他（含领养当天尚未喂） | `hungry` |

**喂食：**
- 已死亡 → 失败，需先复活
- 今天已喂 → 成功但扣 0 粮（防误点）
- 粮 &lt; 1 → 失败
- 否则扣 1 粮，`lastFedDateKey = 今天`

**复活：** 仅 `dead` 且粮 ≥ 3；扣 3 粮，`status = alive`，`lastFedDateKey = 今天`。

**发粮：** 某关 `completedAt` 从空变为有值时 `foodBalance += 1`。同一关重复 complete 不重复发粮。

## 5. 界面与互动

**领养：** 未领养时，主页面弹出选择小猫 / 小狗（大触控区）。不挡底部导航的「去学习」。不强制起名。

**浮窗（可见时）：** 贴在底栏上方右侧。展示精灵、心情文案、粮食数。
- 活着：主按钮「喂一喂」
- 死亡：主按钮「复活」（3 粮）
- 次按钮：隐藏宠物

**隐藏：** 浮窗收成底栏上方一枚小爪印，点一下重新显示。`「我的」` 页同步有「显示宠物」开关。隐藏不暂停饥饿。

**精灵状态：**
- 饱：轻微上下浮动
- 饿：无精打采
- 危急：轻抖 + 「明天不喂会倒下」
- 死亡：灰度倒地

视觉跟现有天蓝 / 草绿 / 暖黄，Fredoka 字体；猫橙、狗金，用 CSS 造型而非再堆一套图标体系。

**完关：** `/api/session/complete` 返回 `foodAwarded`；回今日后浮窗粮食数更新即可，关卡中不插宠物动画。

---

## 6. API

`/api/pet`
- `GET`：当前宠物；无则 `{ pet: null }`。GET 时执行死亡结算。
- `POST { action: "adopt", species, name? }`
- `POST { action: "feed" }`
- `POST { action: "revive" }`
- `PATCH { visible: boolean }`

`POST /api/session/complete` 增加 `foodAwarded: 0 | 1`。

未登录 401。领养冲突 409。粮不够 / 已死亡等业务失败 400，带 `error` 中文文案。

---

## 8. 成功标准

1. 新档案进入主页能领养猫或狗  
2. 完成一关粮食 +1，可囤着改天喂  
3. 点喂食后当天显示饱；连续 3 日不喂后打开应用为死亡  
4. 3 粮可复活  
5. 隐藏后主界面不挡学习，重新显示开关可用  
6. 换设备登录同一档案宠物仍在
